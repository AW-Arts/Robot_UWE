  • Two operation modes: Normal operation vs Teach mode, selectable in the InteractiveArm UI and shown in the demo/video.
  • Project management: Gantt chart must show explicit V&V tasks (simulation, hardware tests, final validation) plus a short risk awareness note.
  • Keep lecturer wording: mirror the marking scheme language so the marker immediately sees the mapping.

Top / High / Low-Level Design Map

Use these figures
  • Top-level design: use “End-to-End Journey & Drilldown Map” as the system overview (operator → UI → controllers → hardware → demo output). Caption it as the top-level system design.
  • High-level design: pair the “Software Architecture” diagram with the “High-Level UI State Machine” to describe subsystems and interactions. Note: Teaching state = Teach mode; Teleop/Playback = Normal operation.
  • Low-level design: select 2–4 flows: Teleoperation, Teach Mode – Waypoints & Subroutines, Autoplay – Timeline Execution, and Safety & Calibration Guardrail. Reference the class diagram sparingly in the body, keep the full function inventory for the appendix.
  • Requirement bullets to lift: R1 Normal mode trajectories, R2 Teach mode waypoint authoring, R3 mode selection via UI, R4 workspace/servo limits in all modes, R5 support for video/simulation evidence.

Operation Modes & Selection

Normal vs Teach
  • Normal operation mode: Teleoperation and Timeline/Playback states execute trajectories on the robot or simulator.
  • Teach mode: Teaching state enables waypoint capture and subroutine saving; autoplay is disabled until you exit.
  • Selection mechanism: mode toggle in InteractiveArm UI (panel switch/button). Entering Teaching locks in teach workflow; returning to Teleop/Playback resumes Normal mode.
  • Demonstration ask: show both modes in the video—highlight the toggle and the distinct behaviours.

Project Management & V&V Visibility

Gantt + risks
  • Gantt must show V&V tasks: add explicit tasks for simulation tests, hardware motion tests, and final validation/demo checks.
  • Text callout: include a sentence like “Verification and validation activities were explicitly scheduled (simulation trajectories, robot tests, final demo checks).”
  • Risk awareness: summarise key risks (hardware limits, calibration drift, missed deadlines) and mitigations.
  • Where to put extras: keep the full function inventory and exhaustive risk register in the appendix; main body gets the summary and the annotated Gantt.

Diagram Standards (Summary)

Conventions
  • Flowcharts use TD/LR orientation, explicit decision nodes and labelled transitions.
  • Labels follow “verb + object” phrasing and align with function names where relevant.
  • State machine is single-active-state, with entry and exit events on transitions.
  • Class diagram shows public methods, basic types and dependency arrows UI → logic → controllers.
  • All diagrams use Mermaid v10 and can be pasted directly into Markdown, MkDocs or Sphinx (with Mermaid plugins).
